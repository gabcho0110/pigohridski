# ПИГ „Св. Климент Охридски“ – София

Уебсайт на училището с административен панел за управление на съдържанието.

- **Сайт:** `index.html` (начало, за училището, прием, новини, паралелки, учители, галерия, документи, контакти)
- **Панел:** `admin.html` (нов правопис на съдържанието без код)
- **База:** Firebase Realtime Database, проект `pigsite-5b862`

Всичко е статично (HTML/CSS/JS) — без build стъпка, без npm. Може да се хоства на GitHub Pages,
Firebase Hosting, Netlify или всеки друг статичен хостинг.

---

## 1. Структура

```
index.html                  публичен сайт
admin.html                  административен панел
assets/css/style.css        стилове на сайта
assets/css/admin.css        стилове на панела
assets/js/content.js        вградено (резервно) съдържание
assets/js/store.js          връзка с Firebase (четене, запис, снимки, вход)
assets/js/app.js            логика на сайта (рутер, изгледи)
assets/js/admin.js          логика на панела
uploads/                    илюстрации по подразбиране
docs/                       публикувани документи (правилник, план, образци)
```

Сайтът първо показва вграденото съдържание от `content.js`, след което — ако има връзка с базата —
го подменя с публикуваното от панела. Така сайтът никога не остава празен.

## 2. Първоначална настройка (еднократно, ~5 минути)

Всичко се прави в [Firebase Console](https://console.firebase.google.com/project/pigsite-5b862).

### 2.1. Включване на вход с имейл и парола

`Authentication` → `Sign-in method` → **Email/Password** → *Enable* → *Save*.

### 2.2. Създаване на администратор

`Authentication` → `Users` → **Add user**:

| Поле | Стойност |
|---|---|
| Email | `atodorov434@gmail.com` |
| Password | `Aleks2010$` |

По желание добавете и втори основен администратор с имейл `admin@pig-ohridski.bg`.

> Имейлите трябва да съвпадат с тези в правилата по-долу (и в `assets/js/store.js`,
> `BOOTSTRAP_ADMINS`). Останалите потребители се създават **от панела** — виж раздел 4.

### 2.3. Правила за достъп до базата

`Realtime Database` → таб **Rules** → поставете това и натиснете **Publish**:

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "content": {
      ".read": true,
      ".write": "auth != null && (auth.token.email == 'admin@pig-ohridski.bg' || auth.token.email == 'atodorov434@gmail.com' || root.child('staff').child(auth.uid).exists())"
    },
    "media": {
      ".read": true,
      ".write": "auth != null && (auth.token.email == 'admin@pig-ohridski.bg' || auth.token.email == 'atodorov434@gmail.com' || root.child('staff').child(auth.uid).exists())",
      "$id": { ".validate": "newData.isString() && newData.val().length < 1200000" }
    },
    "staff": {
      ".read": "auth != null",
      ".write": "auth != null && (auth.token.email == 'admin@pig-ohridski.bg' || auth.token.email == 'atodorov434@gmail.com' || root.child('staff').child(auth.uid).child('role').val() == 'admin')",
      "$uid": { ".validate": "newData.hasChildren(['email'])" }
    }
  }
}
```

С тези правила:

- всеки може да **чете** сайта (необходимо е, за да се зарежда съдържанието);
- само посочените основни администратори и потребителите от възел `staff` могат да **пишат**;
- нови потребители с достъп се добавят от панела (пише се в `staff`);
- всичко останало в базата е затворено.

Същият текст е достъпен и в панела: **Публикуване → Правила за достъп** с бутон „Копирай“.

### 2.4. Вход в панела

Отворете `admin.html` (или „Вход за служители“ горе вдясно на сайта) и влезте с имейла и
паролата от стъпка 2.2. Сменете паролата от **Профил и достъп**.

## 3. Как се работи с панела

| Раздел | Какво управлява |
|---|---|
| **Табло** | кратки статистики и състояние на връзката |
| **Новини** | новини и съобщения (заглавие, дата, категория, резюме, пълен текст, снимка) |
| **Паралелки** | класове, профили, брой ученици, класен ръководител, кабинет |
| **Учители** | име, роля, предмет, биография, снимка |
| **Галерия** | снимки с описание и дата |
| **Документи** | заглавие, категория, връзка към файл |
| **Кариери** | обяви за работа + настройки на формата за кандидатстване |
| **Страници** | свободни страници (клубове, ученически съвет и др.) |
| **Основни данни** | име, адрес, телефони, поща, работно време, карта, социални мрежи |
| **Начало и херо** | първи екран и лентата с цифри |
| **За училището** | текст, принципи, директор, график на звънците |
| **Прием и въпроси** | стъпки, дати, документи, ЧЗВ |
| **Потребители** | кой има достъп до панела и с каква роля (само за администратори) |
| **Публикуване** | публикуване, резервно копие, правила |
| **Профил и достъп** | смяна на парола |

**Важно:** промените се пазят като чернова в браузъра. За да станат видими на сайта, натиснете
**„Публикувай“** (горе вдясно). Докато има непубликувани промени, до заглавието свети жълт надпис.

### Форматиране на текста

В полетата за дълъг текст (новини, страници) работят няколко прости правила:

```
Празен ред          → нов абзац
**удебелен**        → удебелен текст
*курсив*            → курсив
- точка             → списък
[текст](https://…)  → връзка
```

### Снимки

Снимките се качват с бутона „Качи снимка“. Те автоматично се смаляват до 1600 px и се
компресират, за да не забавят сайта. Пазят се в базата (възел `media`), а не в Cloud Storage —
така проектът остава на безплатния план на Firebase.

Ограничение: един файл до ~1 MB след компресия (обикновено достатъчно за снимка от телефон).

## 4. Потребители и достъп

Раздел **Потребители** (в група „Система“) показва кой може да влиза в панела.

### Роли

| Роля | Какво може |
|---|---|
| **Администратор** | всичко — съдържание, публикуване и управление на потребители |
| **Редактор** | променя съдържанието и публикува, но не вижда раздел „Потребители“ |

Два имейла имат постоянен достъп и не могат да бъдат премахнати от панела:
`admin@pig-ohridski.bg` и `atodorov434@gmail.com` (списъкът е в `assets/js/store.js`,
константа `BOOTSTRAP_ADMINS`). Те са и единствените, които могат да пишат в `staff`.

### Нов потребител

1. **Потребители → Нов потребител**
2. попълнете име и фамилия, имейл, парола (мин. 6 знака) и роля
3. **Създай потребител**

Панелът създава акаунта в Firebase Auth (без да изхвърля вас) и записва достъпа в
`staff/<uid>`. Човекът влиза веднага с имейла и паролата, които сте му дали.

### Други действия

| Бутон | Действие |
|---|---|
| ✎ | смяна на име и роля |
| ↻ | изпраща имейл за нова парола (Firebase → шаблон „Password reset“) |
| ✕ | премахва достъпа до панела (акаунтът остава в Firebase) |

> Пълно изтриване на акаунт и смяна на имейл се правят в Firebase Console →
> Authentication → Users. Ако човекът е забравил паролата си, по-лесно е да му изпратите
> имейл с бутона ↻, отколкото да създавате нов акаунт.

> **Ако „Създай потребител“ дава грешка**, най-често Email/Password входът не е включен:
> Firebase Console → Authentication → Sign-in method → Email/Password → Enable (виж 2.1).

## 5. Кариери (обяви за работа)

Страницата `#/karieri` показва обявите, които са маркирани като **видими**, и форма за
кандидатстване с четири полета:

| Поле | Проверка |
|---|---|
| Име и фамилия | задължително, поне две имена |
| Телефон | задължително, 7–15 цифри |
| Имейл | задължително, валиден адрес |
| Година на раждане | четири цифри; **минимум 14 години** |

Възрастта се изчислява спрямо текущата година — не е нужно да се променя ръчно. Ако кандидатът
е роден след допустимата година, формата показва грешка и не изпраща нищо:

> Трябва да сте навършили 14 години, за да кандидатствате. Приемаме кандидати, родени през
> 2012 г. или по-рано.

Минималната възраст се редактира от панела (**Кариери → Минимална възраст**), ако правилото
се промени.

### Събеседване в Discord

Страницата казва изрично, че **събеседванията се провеждат в Discord сървъра на училището** —
веднъж като точка в списъка до формата, и веднъж в отделно блокче под него. След успешно
изпращане екранът с благодарността също споменава, че поканата за събеседване идва през Discord.

| Настройка в панела | Какво прави |
|---|---|
| **Къде се провежда събеседването** | текстът в блокчето „Събеседването е в Discord“. Празно поле = блокчето се скрива |
| **Връзка към Discord сървъра** | по избор; ако е попълнена, под текста се показва бутон „Влез в сървъра“ |

И двете са в **Кариери → Настройки на формата**. Връзката трябва да започва с `https://`
(например `https://discord.gg/xxxxxx`) — иначе не се показва.

### Къде отиват кандидатурите

Директно в Discord чрез **webhook** — не се пазят в базата и не минават през сървър.
Адресът се сменя от панела: **Кариери → Discord webhook адрес**. Бутонът
„Изпрати тестово съобщение“ проверява връзката.

Всяка кандидатура пристига като embed с име, телефон, имейл, година (и възраст) и позиция.

> **Сигурност:** webhook адресът е публичен, както всеки ключ, който работи в браузъра — някой
> може да го използва, за да пише в канала. Затова: пазете канала отделен, следете за спам и при
> нужда го сменете (Discord → канал → Integrations → Webhooks → Delete/New), след което поставете
> новия адрес в панела. Формата има и защита срещу повторни изпращания (45 секунди) и скрито
> поле-капан срещу ботове.

### GitHub Pages

1. `Settings` → `Pages` → *Source*: **Deploy from a branch**, Branch: **main**, папка **/ (root)**.
2. След минута сайтът е на `https://gabcho0110.github.io/pigohridski/`.

`Settings` → `Pages` → *Custom domain* (например `pig-ohridski.bg`), след което в DNS:

```
A     @    185.199.108.153
A     @    185.199.109.153
A     @    185.199.110.153
A     @    185.199.111.153
```

> Ако сайтът е на собствен домейн, добавете го в Firebase: `Authentication` → `Settings` →
> `Authorized domains`, иначе входът в панела няма да работи.

## 7. Технически бележки

- **Без Frameworks.** Ванила JS, без зависимости освен Firebase SDK (compat, v10.12.2 от CDN).
- **Навигация:** хеш-рутер (`#/novini`, `#/novina/<id>`, `#/stranica/<slug>`), така че сайтът
  работи еднакво на всеки статичен хостинг без сървърни пренасочвания.
- **Достъпност:** семантични заглавия, `aria` атрибути, видим фокус, `prefers-reduced-motion`.
- **Печат:** страниците с документи имат отделен печатен стил.
- **Резервно копие:** „Публикуване → Изтегли резервно копие (JSON)“; възстановяване със същия бутон.

### Ограничения

- Панелът е защитен с Firebase Authentication. Ако правилата не са публикувани (стъпка 2.3),
  входът ще работи, но записът ще бъде отказан — появява се съобщение за грешка.
- Снимките в базата не се изтриват автоматично при премахване от галерията (остават като
  неактивни записи в `media`). Това е умишлено — избягва случайна загуба на файлове.
- Документите в `docs/` са HTML страници (отворени за печат като PDF). Може да качите и истински
  PDF файлове в `uploads/` и да поставите пътя им в полето „Връзка към файла“.
- Достъпът до панела се пази във възел `staff/<uid>` (имейл, име, роля). Премахването от панела
  изтрива само този запис — Firebase акаунтът остава и може да бъде добавен отново по-късно.
